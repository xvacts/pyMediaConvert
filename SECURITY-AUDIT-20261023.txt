3. 每项修复的原因、利用条件与改动

A01：提交了疑似真实 API Key。
原 tests/import requests.py 的 xi-api-key 是 64 字符常量；不是空模板或 test_key 示例。
无需本机权限即可从公开代码读取；已确认该值还存在于该文件的一次历史修订中。
未做联网有效性测试，不能断言当前有效或已经被滥用。
改动：脚本只从 ELEVENLABS_API_KEY 环境变量读取；导入不再产生网络请求；只在显式执行 main 时查询。
请求禁止自动重定向，并先检查成功状态再输出 models.json，避免旧代码失败时使用未定义 data。
补充无值 .env.example、忽略 .env.*（保留 example）和审计虚拟环境。
手动脚本不会自动加载 .env，运行前应设置进程环境变量。
必须到 ElevenLabs 撤销/重建；删除代码或清理 Git 历史不能代替撤销。
历史清理需要与协作者协调，不擅自重写仓库或强制推送。

A02：下载归档缺少统一成员边界和资源限制。
原安装器对 TAR 使用 extractall，未拒绝 ../、绝对路径、符号链接、硬链接、设备节点等，
使用恶意 TAR 时存在目录外写入风险；当前启用的下载配置主要使用 ZIP，TAR 路径属于潜在支持面。
Python ZipFile.extractall 本身会规范化部分路径，因此没有把所有 ZIP 的 ../ 都宣称为已证实穿越。
ZIP 仍缺少明确的跨平台成员类型/名称、已有符号链接及解包资源限制。
改动：新增纯标准库 archive_utils.py，安装器和 yt-dlp 更新器共用；先验证全部成员再写入，
拒绝危险路径、Windows 驱动器/ADS/保留名、归档链接/特殊文件及指向链接的目标；
限制 50,000 个成员和 4 GiB 声明解包大小；TAR 权限不保留 setuid/setgid。
正常 ZIP/TAR 与攻击样例均有测试。目标目录应由当前应用持有；不承诺抵御本机攻击者并发改链接。
更新器另校验远程版本号为受支持日期格式，避免远程元数据进入下载/清理路径时携带路径语法。

A03：Gladia 轮询凭据发送目标未校验。
条件：API result_url 元数据异常/被控制，或服务返回跨源重定向；原代码会向该地址发 x-gladia-key，
Requests 对自定义凭据头不能假定具有 Authorization 头相同的跨源保护。
这不是普通用户可以从任意网页直接利用的服务器 SSRF，应用在用户桌面运行且原请求启用 TLS。
改动：result_url 只允许 https://api.gladia.io，默认或 443 端口，无用户信息、控制字符、片段。
提交结果及轮询入口均验证；上传、提交、轮询均禁止自动重定向，非成功状态明确报错。
已对外域/相似域、HTTP、异常端口、userinfo、换行、302 和成功响应测试。
官方接口示例支持该 origin：https://docs.gladia.io/api-reference/v2/pre-recorded/init

A04：日志记录可能携带访问能力的音频 URL 和原始响应内容。
条件：共享日志/报错信息，且 API 返回的 URL 带签名、对象标识或其他敏感内容；原日志直接输出 URL。
改动：成功日志只记录事件；失败不再拼接响应正文/完整 JSON，仍保留 HTTP 状态供定位。
与 A03 一并验证，不声称清除了程序所有业务文本日志；主动开启的调试响应缓存仍需用户妥善保管。

A05：更新检查指向另一个仓库。
旧默认为 secure-artifacts/pyMediaTools。UI 随后可能让用户下载该仓库返回的安装包。
这未证明上游恶意，但使当前 fork 用户的更新信任对象与预期不同。
开发者已明确选择当前仓库；现改为 xvacts/pyMediaConvert，并加入精确请求来源测试。
没有推断当前仓库存在完整发布包，也没有自动下载/执行安装包。

A06/A07：工作流供应链与权限加固。
原 Actions 仅以可移动 vN 标签引用；构建作业继承 contents/id-token/attestations 写权限。
如果 Action 标签被替换或构建依赖遭入侵，影响面可能扩展到发布能力。
改动：将现有同主版本的 7 个 Action 仓库引用固定到 git ls-remote 核实的真实提交；
注释保留 vN，未进行 Action 主版本升级。checkout 不持久化凭据；
发布工作流默认 contents:read，仅 release 作业保留所需写权限。
发布版本从 tag 读取后验证格式，才写入 GITHUB_ENV/被 Bash 或 PowerShell 代码引用。
PyInstaller 的 a 前缀同时正确剥离。正常数字版本和常见 prerelease 后缀仍支持。
没有 pull_request_target 工作流，也未确认无权限 PR 可直接利用版本插值；按纵深防御评级。
验证：3 份工作流 YAML 可解析，所有 uses 都是 40 位提交固定；完整 Actions 运行尚待确认。

A08：构建额外获取 master 源码覆盖 pip 依赖。
requirements 安装与动态源码打包原来可能使用完全不同版本；仅检查 pip 版本无法覆盖实际发布内容。
开发者选择正式标签后，安装器现在从已安装 yt-dlp 元数据计算正式日期标签，正确补齐月/日前导零。
非正式/dev 或无效日期显式失败，不悄悄退回 master；5 个附加测试覆盖该选择。
标签固定不等于签名/独立哈希验证，后者仍是 A09。

6. 保留风险与需要取舍的事项

A09：下载可执行文件/源码尚无独立可信哈希或签名验证，FFmpeg Windows 仍是 latest。
利用前提包括上游发布/账户、信任链或实际下载内容被控制；并未发现本次下载已被篡改的证据。
方案：维护经审核的版本+平台+SHA256 清单，或验证可信发布证明/签名，再将下载与原子替换绑定。
建议作为发布流程变更实施，并同时固化依赖锁和二进制清单。本轮没有编造哈希或移除更新功能。
当前解压器的资源上限不限制网络下载总大小；断网/磁盘满/替换中断还需恢复与并发更新测试。

A10：多个 API Key 被保存到 QSettings（Windows 注册表/平台设置存储），配置 TOML 也支持密钥字段。
有本机用户/备份访问权限的代码可能读取；密码输入框不等于加密保存。
开发者明确选择本轮保留保存功能、记录风险，后续单独迁移系统凭据库。
建议用 Windows Credential Manager/macOS Keychain 等，并设计迁移成功后删除旧值和失败恢复。
没有擅自新增凭据库依赖、删除用户配置或把自造加密当作保护。

A11：无版本约束和锁文件，包管理器可能解析到新的主版本；新安装可复现性不足。
当前审计环境 OpenCV 已解析为 5.x，不能把测试环境选择等同于生产批准的大版本升级。
建议分别为支持的平台/Python 生成锁与哈希，在兼容性通过后再采用；本轮未重写 requirements.txt。

媒体/字幕/字体均会送入原生解析库；本次没有 fuzzing 或沙箱验证。
子进程重点调用使用参数列表或 QProcess.start(program,args)，扫描未发现 shell=True、
os.system、eval/exec、pickle.load 或不安全 yaml.load 的活动调用；这不等于 FFmpeg 输入格式绝对安全。
本项目不是 Web 服务，没有 SQL/NoSQL、服务端鉴权、Cookie 会话、CORS、CSRF、Electron IPC 等接口；
没有将用户主动选择本机文件路径或下载 URL 本身认定为服务器路径穿越/SSRF。
